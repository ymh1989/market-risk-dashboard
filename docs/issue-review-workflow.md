# 시장 이슈 개인 승인함

## 역할 분리

- 공개 `시장 이슈` 탭: 승인된 상시 주제·개별 사건, 활성·관찰·보관, 근거 기사·지표·상태 이력
- 비공개 SQLite: 미승인·반려 후보, Telegram 사용자 ID, 메시지 번호, 일회용 값, 감사 기록
- 로컬 Qwen: 후보와 전환 제안만 생성. 승인·점수 변경·명령 실행 권한 없음
- 기존 6개 상시 주제 유지. 신규 사건의 수준은 연결 주제의 기존 카드 판독이며 별도 사건 점수가 아님
- 미승인 후보는 Git, GitHub Pages, 오프라인 HTML에 미포함

## 신규 후보

1. 개인 승인 서비스가 한국시간 07:45 이후 하루 한 번 공개 금융·경제 RSS 탐색
2. 기존 6개 주제의 검색어와 별도로 정책·신용·금융불안 등 4개 폭넓은 검색어 사용
3. 최근 7일 중 최대 24개 제목, 기존 사건, 허용된 지표를 로컬 모델에 전달
4. 신규 최대 2개·전환 최대 2개 제안. 제공된 기사 ID·지표 ID·문자 길이·검색어 형식 검증
5. 신규는 위험 근거가 제목에 확인되는 기사 2건·서로 다른 매체 2곳·선택 주제 내 현재 이용 가능한 지표 2개 이상 필요. 일반 협력·행사 보도 제외
6. 중복·이미 승인된 사건 근거를 재사용한 후보 억제. 반려한 동일 후보는 7일 동안 재알림 억제

매체 수는 독립 취재 확인이 아니다. 후보는 제목 기준의 검토 대상이며, 승인자는 링크에서 본문·중복 인용·관련성을 확인해야 한다.
임계치와 기간은 보수적인 초기 운영 규칙이며 예측성능이 검증된 기준은 아니다.

## 상태 전환

- 활성 → 관찰: 실제 원자료 관측일 3회 연속 완화, 연결 카드 75점 미만, 반대 위험신호 없음
- 관찰 → 보관: 관찰 승인일 이후 관측일 5회 안정·완화, 연결 카드 75점 미만, 반대 위험신호 없음
- 관찰·보관 → 활성: 최신 지표 2개 이상 악화 확인
- 공통: 최신 시장 스냅샷 26시간 이내, 완전한 지표, 뉴스 조회 정상, LLM의 관련 기사 근거, 본인 승인. 관측 묶음은 최근 21일 이내, 마지막 관측은 5일 이내
- 반복 장중 배치는 같은 관측일로 합산. 뉴스 감소·자료 누락·수집 실패만으로 전환 금지
- 보관 시점의 기사·차트·판독을 고정 저장. 백그라운드 관측은 계속해 재활성 후보 탐색
- 삭제 기능 없음. 상태 변경 이유·시간·이전 버전 보존

## 개인 인증과 승인

- 기존 대시보드 봇 `TELEGRAM_BOT_TOKEN` 또는 별도 `ISSUE_REVIEW_TELEGRAM_BOT_TOKEN` 사용
- 같은 봇에 `getUpdates` 수신기를 중복 실행하지 않음. 기존 webhook이 있으면 설치된 수신기는 시작 거부
- 설치 후 발급한 일회용 연결 링크로 개인 대화에서 등록. 192비트 난수, 20분 만료, 원문 미저장
- 최초 등록 뒤 다른 링크로 관리자 덮어쓰기 금지. 계정 교체는 로컬 관리자가 별도로 처리
- 그룹 승인·계정 불일치·봇 계정·다른 메시지·잘못된 난수·48시간 지난 후보 거부
- 승인 시 시장자료·전환 조건·대상 버전을 다시 확인. 반복 클릭은 한 번만 반영
- 승인과 감사 이력·게시 대기 상태를 같은 트랜잭션에서 기록
- Telegram 확인 응답이 실패해도 이미 저장한 승인은 다시 실행하지 않음
- `/issues`: 검토 대기 재전송. 새 메시지로 교체하면 예전 메시지 버튼은 무효
- `/status`: 후보 탐색·게시 대기 상태 확인

Telegram 공식 규격: [개인 메시지·콜백·수신 오프셋](https://core.telegram.org/bots/api).
등록 링크도 일회용 인증정보이므로 다른 사람에게 전달하지 않는다.

## 게시와 장애

- 승인 후 고정된 운영 실행기의 `--live` 갱신을 요청. 모델 문장을 셸 명령으로 사용하지 않음
- 기존 운영 잠금·품질 검사·원자적 게시·원격 검증 경로 사용
- 등록부와 버전을 같은 트랜잭션에서 읽어 갱신 중 새 승인의 혼입 방지
- 실제 홈페이지의 승인 등록부 버전을 확인한 뒤 반영 완료 알림. 미확인 시 5분 뒤 재시도
- 정기 배치도 승인 등록부를 반영. 로컬 저장소가 없거나 CI이면 마지막 공개 승인 등록부 보존
- 후보 탐색 실패는 1시간 뒤 재시도. 기존 시장 갱신과 승인 이슈는 유지
- 코드만으로 사실 검증·위험 해소를 확정하지 않음. 사람의 판단과 근거 확인 필요

## 설치

영구 작업폴더에서 실행한다. 임시폴더에서는 LaunchAgent 설치를 거부한다.
운영 실행기의 기본 비공개 경로는 `<운영 폴더>/logs/issue-review`이며 폴더 권한 700, DB 권한 600이다.

```sh
python scripts/install_issue_review_launchd.py \
  --env-file /절대경로/market-lab/.env \
  --state-dir /절대경로/운영폴더/logs/issue-review \
  --runtime /절대경로/운영폴더

python scripts/run_issue_review_bot.py \
  --env-file /절대경로/market-lab/.env \
  --state-dir /절대경로/운영폴더/logs/issue-review --pair
```

서비스: `com.marketlab.issue-review`. `bot.log`, `bot.err.log`, `publication.log`는 비공개 경로에 저장한다.
코드 업데이트 후에는 영구 작업폴더를 검증된 커밋으로 갱신하고 설치 명령으로 서비스를 재시작한다.
SQLite 백업은 실행 중 파일 단순 복사 대신 SQLite backup API를 사용한다.

## 검증

```sh
PYTHONPATH=src python -m pytest -q tests/test_issue_review.py tests/test_issue_radar.py tests/test_issue_radar_llm.py tests/test_offline_export.py
node --test tests/dashboard_ui.test.cjs
```

테스트의 합성 후보는 임시 DB에서만 사용한다. 운영 검증을 위해 자동 승인하거나 가짜 후보를 실제 검토함에 넣지 않는다.
