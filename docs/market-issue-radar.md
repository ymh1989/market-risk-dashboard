# 시장 이슈 레이더

## 목적과 화면

- 주요 뉴스와 시장 가격의 반응을 나란히 확인하는 관찰 도구
- 통합 요약: 위험 우선 3개 이슈, 클릭 시 시장리스크 상세로 이동
- 시장리스크: 승인 이슈 6개, 위험/보도순 정렬, 악화/경계 필터, 개인별 상단 고정
- 상세: 공개 기사 링크, 위험 전파 점검 경로, 후속 확인 항목, 원자료 수준과 변화
- 차트: 공통 기간 선택과 날짜 커서, 보관 기사 첫 보도일 점선
- 기존 시장리스크 점수·그룹 가중치·ML·ELS 산식 변경 없음

## 데이터와 판독

`config/market_issues.json`에서 이슈·검색어·연결 지표를 관리한다. `approved: true`만 게시한다.
프랑스·유럽 재정, 금리, 에너지, 달러 조달, 국내 수급, 반도체를 초기 대상으로 사용한다.

- 뉴스: Google News 공개 RSS의 제목·매체·링크·발행시각만 수집. 사내 뉴스/텔레그램 본문 접근 없음
- 검색: 최근 7일, 보관: 최근 30일·이슈당 최대 60건. 동일 제목·URL 제거
- 뉴스 건수: 수집 표본의 제목 수이며 전체 보도량이나 독립 사건 수가 아님
- 상세 기사: 시장 관련어를 포함한 제목을 우선하고 그 안에서 최신순 3건 표시. 본문 사실관계 자동 검증 기능은 아님
- 성공 응답 한 시간 캐시. 조회 실패 시 보관 기사와 마지막 성공 조회시각 유지, 최신 집계 미확인 표시
- 위험 수준: 연결된 기존 카드의 최신 유효 점수 중 최댓값. 55 이상 주의, 75 이상 경계. 신규 종합점수가 아님
- 방향: 원자료의 5개 관측 전 대비 변화. 기준폭 이상 같은 방향 2개 이상이고 반대 신호가 없으면 악화/완화
- 유효 지표 2개 미만이면 판독 대기. 오래된 원자료를 0이나 정상으로 대체하지 않음
- 금리 변화는 bp, 비율 변화는 %p, 가격 변화는 %로 구분. 1W는 5개 관측 전 기준이며 비교일을 함께 저장
- 주가 비율은 공통 관측일만 사용하고 최초 공통일을 100으로 환산. 결측 날짜 보간 없음
- DRAM 가격은 상승·하락의 위험 의미가 양면적이므로 맥락 정보로만 표시
- 5영업일 초과 자료는 판독 제외. 글로벌 공통 평일 기준이므로 현지 공휴일 영향 가능

방향 기준폭은 코드의 `metric_catalog()`에 명시한 초기 관찰 규칙이다. 예측력이 검증된 경보모델이나 인과 추론이 아니다.
첫 보도일은 현재 보관한 기사 중 가장 이른 발행일로, 사건 발생일이나 최초 시장 인지일을 뜻하지 않는다.
비교 기준값은 첫 보도일 **직전** 관측값이며, 10일 이내 값이 없으면 표시하지 않는다.
기사가 보관 범위에서 빠지면 기준일도 이동할 수 있다. 특정 사건의 장기 성과 검증에는 별도의 고정 사건일이 필요하다.
예정 일정은 승인된 설정만 표시하며 뉴스 문장에서 자동 추정하지 않는다.

## 실행과 게시

```sh
python3 scripts/update_issue_radar.py
python3 scripts/update_issue_radar.py --offline
```

- 기존 `data/risk-dashboard.json`의 `market.issueRadar`에 저장
- 시장 원자료의 `metadata.generatedAt`은 변경하지 않고 레이더 조회시각만 별도 기록
- 정기 갱신의 품질 검증 직전에 실행. 별도 스케줄이나 추가 인증키 불필요
- 기존 원자적 게시 묶음과 오프라인 HTML에 포함. 오프라인에서 필터·차트·고정 사용 가능
- 오프라인 기사 본문은 포함하지 않으며 링크 열기는 인터넷 연결 필요
- 뉴스 조회 장애는 레이더에 표시하고 기존 시장 데이터 갱신을 중단하지 않음

## 로컬 LLM 선별

- 기본 모델: 기존 브리핑과 같은 Ollama `qwen3.5:9b-q4_K_M`
- 후보: 이슈당 최근 7일 기사 중 주제 적합성을 확인한 최대 12건. 공개 제목·매체·발행시각으로 관리
- 모델 입력: 제목·매체·발행시각·짧은 요청 ID·원자료 판독 방향·승인된 점검 항목. 긴 기사 ID는 결과 검증 후 복원
- 역할: 직접 관련된 기사 최대 3건, 점검 지표 최대 2개, 우선 점검 항목 선택
- 본문 미수집. 제목만으로 관련성을 확인하지 못하면 기사 선택을 비워둘 수 있음
- 자유 문장·위험등급·점수·새 사건·수치 생성 금지. 제공된 ID와 항목 번호만 구조화 출력으로 수신·검증
- 화면의 짧은 자료 점검문은 선택된 지표의 실제 변화량으로 코드가 구성. AI가 인과관계를 입증한 것은 아님
- 최대 3개 주제씩 나눠 요청. 관련 기사 입력이 있는데 빈 선택이면 최대 2개 주제만 한 번 재검토. 빈 응답을 강제로 채우지 않음
- 단순 채권 발행 성공·개인 가정 시나리오·점검 지표와 국가가 다른 기사를 구분하고 악화뿐 아니라 완화 근거도 허용
- 입력·모델·프롬프트가 같으면 최대 24시간 선별 캐시 재사용
- 기사·판독 방향·관측일 변경 시 재선별. 숫자만 바뀌어도 화면의 변화량은 항상 현재 원자료 사용
- 요청별 기본 응답 대기 45초, 최대 설정 60초. 통신 실패는 즉시 재시도하지 않으며 실패한 묶음 외의 정상 결과는 보존. 장애 후 30분 대기하고 키워드 방식 유지
- 로컬 루프백 HTTP만 허용. 프록시·외부 리다이렉트 차단. 외부 LLM·사내 뉴스·계좌정보 전송 없음
- CI와 `--offline`에서는 모델 미호출. 입력이 일치하는 유효 보관 선별은 원래 생성시각으로 표시
- `ISSUE_RADAR_LLM_ENABLED=0`으로 신규 선별 중지. 모델은 `ISSUE_RADAR_LLM_MODEL`, 주소는 `ISSUE_RADAR_OLLAMA_URL`로 설정
- LLM이 새 이슈를 자동 공개하지 않음. 별도 [개인 승인함](issue-review-workflow.md)에서 하루 세 회차 신규·전환 후보를 검토하고 본인 승인 후 반영
- 상시 주제의 검색어는 최신 설정을 적용하되 승인된 사건의 검색어·상태·지표·가중치는 유지
